# Phase 2 — UI/UX Direction

## Design Goal

The website should be **minimal, technical, modern, and slightly distinctive** without looking like a UI/UX designer portfolio.

### Recommended Style

Use a clean developer-focused interface with:

- Dark or neutral background
- Strong typography
- Plenty of spacing
- Subtle gradients or glow effects
- Small technical visual details
- Architecture diagrams
- Code/API snippets
- AWS/cloud-inspired visuals
- Minimal animations
- Responsive layout
- Fast loading

### Possible Unique Element

Instead of relying on decorative graphics, use technical components as visual elements:

- API request/response cards
- Terminal-style command snippets
- System architecture diagrams
- Deployment pipeline visualization
- AWS infrastructure flow
- Tech-stack cards
- Service status indicators
- JSON/code previews

These should make the portfolio visually interesting while staying aligned with my niche.

### Avoid

- [ ] Excessive animations
- [ ] Overdesigned glassmorphism everywhere
- [ ] Too many colors
- [ ] Large decorative 3D objects
- [ ] UI/UX mockup-heavy sections
- [ ] Too many frontend-only projects
- [ ] Generic developer portfolio templates
- [ ] Skill percentage bars such as "JavaScript 95%"

# Final Portfolio Identity

The portfolio should NOT communicate:

> I am a frontend developer who also knows some backend.

It should communicate:

> I am a software engineer focused on backend systems, APIs, AWS, and DevOps who can also build and integrate frontend applications when needed.

The UI/UX exists to reinforce this technical identity.

## Core Principle

**Show systems, architecture, engineering decisions, APIs, deployments, and problem-solving — not just screenshots.**
